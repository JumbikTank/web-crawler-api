# Web Crawler API — ДЗ, часть 1

Клиент-серверное приложение для скачивания и анализа **заданного списка веб-страниц**.
Пользователь передаёт URL, сервер скачивает HTML, сохраняет страницы и их метаданные,
позволяет получить текст и возвращает результат обработки каждого адреса.
Ссылки внутри HTML не запускают новые скачивания: рекурсивного обхода интернета нет.

В первой части реализован сервер. Будущий клиент сможет отправлять список адресов,
показывать результаты и открывать сохранённые страницы. Проверить API сейчас можно
через curl или Swagger UI.

**Стек:** Python 3.12, Litestar, msgspec, aiohttp, **selectolax 0.4.12 / Lexbor**,
Protego, SQLite. Дополнительное хранилище — DynamoDB + S3 через aioboto3.
[Selectolax](https://selectolax.readthedocs.io/en/latest/) использует нативный HTML5-парсер
[Lexbor на C](https://www.lexbor.com/modules/html/); Python `HTMLParser` не используется.

Из [исходной схемы](https://jumbiktank.github.io/internet-crawler/internet_crawler.svg)
взяты загрузка списка URL, проверка robots.txt, скачивание, хранение HTML и метаданных,
извлечение текста и дедупликация. Учебная версия обрабатывает явно заданные адреса;
распределённая архитектура и масштабы схемы описаны отдельно в
[описании границ проекта](web_crawler_product_description.md).

## Функциональные требования — 10

| № | Требование | Реализация и критерий приёмки |
|---|---|---|
| F1 | Принимать список URL для обработки. | `POST /crawl`: 1–20 HTTP(S)-адресов; повторы точной строки URL внутри запроса обрабатываются один раз. |
| F2 | Скачивать HTML по заданным адресам. | Сервер выполняет HTTP GET, следует не более чем по 5 перенаправлениям; ссылки из содержимого страницы не посещает. |
| F3 | Учитывать robots.txt перед скачиванием. | Проверяется разрешение для `StudyCrawler/1.0`, в том числе на целевом адресе перенаправления; запрещённая страница не запрашивается. |
| F4 | Возвращать отдельный результат для каждого URL. | Ответ `/crawl` содержит `items`, `saved`, `failed`; успешный элемент — `status=saved`, ошибка — `status=failed` с кодом и пояснением. Ошибка одного адреса не отменяет остальные. |
| F5 | Сохранять скачанный HTML и метаданные страницы. | В хранилище записываются HTML, исходный `url`, `s3_link`, SHA-256 `content_hash`, `last_crawled_time`. Повторное скачивание обновляет запись URL. |
| F6 | Читать сохранённый HTML по URL. | `GET /html?url=…`: строка `html_content` в JSON или `404`, если содержимое отсутствует. |
| F7 | Извлекать текст сохранённой страницы. | `GET /text?url=…`: текст тела документа через selectolax/Lexbor, без `head`, `script`, `style`, `noscript`, `template`; HTML-сущности декодируются, пробелы нормализуются. |
| F8 | Дедуплицировать HTML по содержимому. | Одинаковый HTML в UTF-8 у разных URL получает одинаковый SHA-256 и один ключ хранения; разметка перед хешированием не нормализуется. |
| F9 | Просматривать каталог метаданных и искать страницы по хешу. | `GET /url-data?url=…` возвращает запись или `404`; `GET /urls` поддерживает `limit`, `cursor`, `content_hash`. |
| F10 | Удалять URL из каталога. | `DELETE /url-data?url=…`: `204`; повторное чтение записи — `404`. Общий HTML других URL не удаляется. |

Проверки: [tests/test_crawl.py](tests/test_crawl.py),
[tests/test_integration.py](tests/test_integration.py),
[tests/test_services.py](tests/test_services.py).

## Нефункциональные требования — 10

| № | Требование | Критерий и проверка |
|---|---|---|
| N1 | Сохранять результаты между запусками. | После перезапуска с тем же SQLite-файлом доступны прежние HTML и метаданные; `test_restart_persistence`. Текст извлекается из сохранённого HTML при чтении. |
| N2 | Проверять запросы до скачивания или записи. | HTTP(S)-адрес до 2048 символов без логина, пароля и пробелов; хеш — 64 строчные hex-цифры; неизвестные поля запрещены. Ошибки — `400`; тесты моделей и `/crawl`. |
| N3 | Ограничивать потребление ресурсов. | HTML ≤ 1 МиБ при чтении сети и после декодирования в UTF-8; robots.txt ≤ 512 КиБ; тело API-запроса ≤ 8 МиБ; `/crawl` ≤ 20 URL; страница каталога ≤ 100 записей. Тесты размеров и потокового чтения. |
| N4 | Быстро выдавать страницы локального каталога. | p95 < 200 мс для `GET /urls?limit=20` на 1000 записях, один клиент, 5 прогревочных и 50 измеряемых запросов через ASGI TestClient; `test_local_list_latency`. Это не время скачивания внешнего сайта. |
| N5 | Ограничивать параллелизм и частоту обращений к сайтам. | Не более 4 обработок URL одновременно на процесс, один запрос к одному origin одновременно, пауза не менее 1 с после ответа; больший `Crawl-delay` или интервал `Request-rate` учитывается. Проверки downloader и HTTP-фикстуры. |
| N6 | Завершать неуспешные скачивания за ограниченное время. | 10 с на HTTP-запрос, 30 с на обработку URL после получения слота, включая robots.txt и перенаправления; ошибки сети, типа/размера ответа и хранилища возвращаются отдельным элементом результата. Автоматических повторов нет. |
| N7 | Ограничивать скачивание публичной сетью. | Проверяются IP-литералы, результаты DNS и каждый redirect; loopback, private и link-local адреса запрещены. Подключение идёт к проверенному IP, proxy-переменные окружения не используются; тесты адресов и DNS resolver. |
| N8 | Выполнять разбор HTML без запуска кода страницы. | HTML5 разбирается selectolax/Lexbor; JS не исполняется, ресурсы и ссылки не загружаются. HTML и текст выдаются как JSON; `test_native_html_extraction`, `test_real_http_download_without_recursive_requests`. |
| N9 | Обеспечивать воспроизводимый и конфигурируемый запуск. | Python 3.12 + `uv sync --frozen`, зависимости закреплены в `uv.lock`; SQLite не требует AWS. Путь БД и AWS-настройки — в окружении, секреты не коммитятся. |
| N10 | Поддерживать автоматические проверки качества. | Покрытие серверного кода ≥ 90%; pytest, Ruff, Black, isort и строгий mypy проходят. Команды ниже и workflow `.github/workflows/checks.yml`. |

## Запуск

Нужен [uv](https://docs.astral.sh/uv/getting-started/installation/).

```bash
git clone https://github.com/JumbikTank/web-crawler-api.git
cd web-crawler-api
uv sync --frozen
uv run --frozen uvicorn crawler.app:app --host 127.0.0.1 --port 8000
```

- API: <http://127.0.0.1:8000>
- Swagger UI: <http://127.0.0.1:8000/schema/swagger>
- OpenAPI JSON: <http://127.0.0.1:8000/schema/openapi.json>
- Проверка HTTP-сервера: <http://127.0.0.1:8000/health>

По умолчанию данные хранятся в `data/crawler.sqlite3`.
Приложение предназначено для локальной демонстрации: каталог общий, аккаунтов нет.
`/health` проверяет работу HTTP-приложения, а не доступность AWS или внешних сайтов.

Для своей конфигурации:

```bash
cp .env.example .env
# Изменить нужные значения в .env
uv run --frozen uvicorn crawler.app:app --env-file .env --host 127.0.0.1 --port 8000
```

## Пример: скачать страницы и получить текст

```bash
curl http://127.0.0.1:8000/crawl \
  -H 'Content-Type: application/json' \
  -d '{"urls":["https://example.com","https://example.org"]}'

curl -G http://127.0.0.1:8000/text --data-urlencode 'url=https://example.com'
curl -G http://127.0.0.1:8000/html --data-urlencode 'url=https://example.com'
curl -G http://127.0.0.1:8000/url-data --data-urlencode 'url=https://example.com'

curl 'http://127.0.0.1:8000/urls?limit=20'
curl http://127.0.0.1:8000/stats
```

`POST /crawl` отвечает после завершения обработки списка. HTTP `200` означает,
что пакет обработан: результат каждого адреса нужно смотреть в `items`.
Успешный элемент содержит исходный `url`, `final_url` после перенаправлений,
`http_status`, `s3_link`, `content_hash`, `last_crawled_time`, `status: "saved"`.
Ошибка содержит `status: "failed"`, `error` и `detail`.
Метаданные сохраняются под исходным URL; `final_url` доступен в ответе обхода.
Результаты неуспешных попыток возвращаются в ответе, но отдельно в БД не записываются.

Текст вычисляется при `GET /text` из сохранённого HTML; повторный сетевой запрос
к сайту для этого не нужен. Это текст узлов HTML, а не результат визуального
рендеринга: CSS-видимость и JS-содержимое не вычисляются.

При длинном списке запрос ожидает освобождения слотов; лимит 30 с относится
к отдельному URL после получения слота. Для демонстрации используется один процесс
Uvicorn: ограничения параллелизма и кеши действуют внутри процесса.

### Правила скачивания

- Запрашиваются только переданные URL, их HTTP-перенаправления и необходимые `robots.txt`.
- User-Agent — `StudyCrawler/1.0`. Правила robots.txt разбирает Protego; кеш действует
  1 час и содержит не более 1024 записей, DNS-кеш — 60 с.
- Отсутствие robots.txt (`404`/`410`) допускает скачивание. При запрете, ошибке доступа,
  сетевой ошибке или слишком большом robots.txt страница не скачивается.
- Принимаются `text/html` и `application/xhtml+xml` с HTTP `200`.
  Запрашивается несжатый ответ (`Accept-Encoding: identity`); если сайт принудительно
  отправляет сжатие, возвращается ошибка `encoding`.
- HTML декодируется по charset HTTP-ответа, иначе по UTF-8; неизвестный charset
  заменяется на UTF-8, некорректные байты — символом замены. В архиве хранится
  декодированный HTML, SHA-256 считается по его UTF-8 представлению.

## Остальные методы API

Сохранены вспомогательные методы исходного проекта:

| Метод | Назначение |
|---|---|
| `POST /html` | Загрузить готовый HTML вручную: `{"url":"https://example.com","html_content":"<p>Hello</p>"}`. |
| `POST /urls` | Создать или полностью заменить метаданные URL. |
| `POST /urls/batch` | Зарегистрировать 1–100 URL без скачивания; существующие записи сохраняются. |
| `GET /stats` | Число URL, число записей с хешем и число уникальных хешей в метаданных. |
| `DELETE /url-data?url=…` | Удалить URL из каталога. |

Поле `s3_link` сохранено для совместимости: локально имеет вид `sqlite://html/<hash>`,
в AWS — `s3://bucket/html/<hash>.html`. Это идентификатор хранения, не HTTP-ссылка.
Время — целое число секунд Unix UTC. При ручной регистрации URL сервер подставляет
текущее время, если оно не задано; регистрация сама по себе не означает скачивания.

`POST /urls` полностью заменяет метаданные: пропущенные поля становятся `null`.
Для повторной регистрации без потери полей используйте `POST /urls/batch`.
Идентичность URL определяется точным совпадением строки.

Для следующей страницы `GET /urls` передавайте `next_cursor` через `--data-urlencode`
с тем же фильтром `content_hash`. `null` означает конец. SQLite сортирует URL
лексикографически. В DynamoDB используется `Scan`, поэтому страница после фильтрации
может быть пустой и всё же иметь следующий курсор. Курсоры зависят от режима хранения.

## Проверки

```bash
uv sync --frozen --extra dev
uv run --frozen pytest
uv run --frozen ruff check crawler tests
uv run --frozen black --check crawler tests
uv run --frozen isort --check-only crawler tests
uv run --frozen mypy crawler tests
```

Тесты работают с временной SQLite и контролируемым локальным HTTP-сайтом;
доступ к настоящим сайтам и AWS не требуется. Для HTTP-фикстуры используется отдельный
тестовый resolver, которого нет в конфигурации приложения. AWS-адаптеры проверяются
с моками. Покрытие формируется в `htmlcov/index.html`, порог 90% задан в `pyproject.toml`.

## Дополнительный режим AWS

Установить `STORAGE_BACKEND=aws`. Нужны заранее созданные ресурсы:

- DynamoDB-таблица `DYNAMODB_TABLE`, partition key `url` типа String, без sort key;
- S3-бакет `S3_BUCKET` в регионе `AWS_DEFAULT_REGION`;
- credentials через профиль boto3, переменные окружения или IAM role;
- права DynamoDB `PutItem`, `GetItem`, `Scan`, `DeleteItem` и S3 `PutObject`, `GetObject`.

`AWS_ENDPOINT_URL` позволяет указать совместимый эмулятор.
Для одного физического S3-объекта на хеш нужен бакет без versioning:
повторная запись в бакет с versioning создаёт новую версию.
Проверка на реальном AWS не входит в локальный прогон. GSI из архитектурной схемы
не реализован, список и фильтрация используют `Scan` и рассчитаны на небольшой каталог.

## Структура и ограничения

```text
crawler/
  app.py         # API скачивания, чтения, поиска и удаления
  downloader.py  # aiohttp, robots.txt, таймауты и ограничения сети
  extraction.py  # Извлечение текста: selectolax / Lexbor
  models.py      # Контракты и валидация msgspec
  config.py      # Конфигурация хранилища
  local.py       # SQLite
  services.py    # DynamoDB и S3
tests/
  test_crawl.py        # Скачивание, robots.txt, native-парсер, HTTP-фикстура
  test_integration.py # API и настоящая SQLite
  test_app.py         # Отдельные HTTP-маршруты
  test_services.py    # AWS-адаптеры
```

HTML сохраняется до обновления метаданных; при сбое второй записи возможен объект
без ссылки. Удаление URL не удаляет общий HTML; автоматической очистки таких объектов нет.
Статистика считает метаданные, а не проверяет наличие каждого объекта в S3.
Пакетная регистрация проверяет все адреса до записи, но не является общей транзакцией.
Выполняющийся HTTP-запрос `/crawl` не восстанавливается после перезапуска сервера;
уже сохранённые страницы остаются, список можно отправить повторно.

Справочные материалы: [aiohttp](https://docs.aiohttp.org/en/stable/client_advanced.html),
[selectolax / Lexbor](https://selectolax.readthedocs.io/en/latest/lexbor.html),
[Protego](https://github.com/scrapy/protego),
[Litestar](https://docs.litestar.dev/2/usage/requests.html).
