# Парсер всего интернета - Техническое описание продукта

## Жизненный цикл продукта

### 1. Идея и планирование
- **Цель**: Создать масштабируемую систему для парсинга всего интернета
- **Масштаб**: 5 миллиардов URL за неделю, 10-30 тысяч страниц в секунду
- **Технические ограничения**: 1 МБ на страницу, время скачивания 1 секунда

### 2. Разработка архитектуры
- Проектирование распределенной системы с балансировщиком нагрузки
- Выбор технологий: Kafka, Flink/Quix, SQS, DynamoDB, S3
- Реализация алгоритмов партицирования и кеширования

### 3. Развертывание и масштабирование
- Настройка инфраструктуры (3 сервера по 300 Гбит/сек)
- Конфигурация балансировщика и очередей
- Мониторинг производительности

### 4. Поддержка и оптимизация
- Мониторинг загруженности серверов
- Обновление кешей (DNS, robots.txt, HTML)
- Дедупликация контента

## Ключевые требования к системе

### Функциональные требования
- **Парсинг**: Обработка 5 млрд URL за неделю
- **Производительность**: 10-30 тыс страниц/сек
- **Дедупликация**: Избежание повторной обработки контента
- **Соблюдение robots.txt**: Проверка правил краулинга

### Нефункциональные требования
- **Масштабируемость**: Горизонтальное масштабирование через партицирование
- **Отказоустойчивость**: Сохранение состояния между рестартами (Flink/Quix checkpoints)
- **Производительность**: Локальное кеширование для минимизации сетевых вызовов
- **Надежность**: Репликация критических данных

### Технические ограничения
- **Пропускная способность**: 12.5 ГБ/сек (треть от доступной)
- **Размер страницы**: 1 МБ в среднем
- **Время обработки**: 1 секунда на страницу

## Контексты в терминах DDD

### Bounded Context: "Web Crawling"

**Основные сущности:**
- `URL` - адрес веб-страницы для парсинга
- `Domain` - доменное имя с правилами robots.txt
- `Content` - HTML контент страницы
- `CrawlJob` - задача на парсинг

**Агрегаты:**
- `CrawlSession` - сессия краулинга с состоянием
- `DomainRules` - правила парсинга для домена

**Сервисы домена:**
- `URLPartitioner` - распределение URL по серверам
- `ContentDeduplicator` - проверка дубликатов
- `RobotsChecker` - валидация правил краулинга

### Внешние контексты

**"Infrastructure Management"**
- Управление серверами и балансировщиками
- Мониторинг производительности
- Конфигурация DNS и прокси

**"Content Storage"**
- S3 для хранения HTML и текста
- DynamoDB для метаданных URL
- Redis для локального кеширования

**"Queue Management"**
- Kafka для распределения задач
- SQS для очередей парсинга
- Flink/Quix для обработки потоков данных

**"External Web"**
- HTTP запросы к веб-сайтам
- DNS резолвинг
- Обработка robots.txt файлов

### Интеграции между контекстами
- **Crawling → Storage**: Сохранение результатов парсинга
- **Crawling → Queue**: Постановка новых URL в очередь
- **Infrastructure → Crawling**: Предоставление вычислительных ресурсов
- **External Web → Crawling**: Получение веб-контента
