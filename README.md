# Web Crawler API — ДЗ, часть 1

Сервер клиент-серверного приложения для хранения результатов веб-краулинга.
Пользователь (аналитик или разработчик краулера) регистрирует URL, загружает
полученный HTML, читает сохранённые страницы и находит URL с одинаковым содержимым.
Будущий клиент будет предоставлять формы загрузки и просмотра архива.
В этой части реализован только сервер; для проверки достаточно HTTP-запросов или Swagger UI.

**Стек:** Python 3.12, Litestar, msgspec, SQLite; дополнительный режим — DynamoDB + S3
через aioboto3. Исходные AWS-адаптеры и три маршрута проекта сохранены и расширены.
Локальный режим работает без AWS, Docker и облачных ключей.

Сервер принимает **готовый HTML** и сам не скачивает сайты. Распределённое скачивание,
robots.txt, очереди и обработка миллиардов URL — дальнейшее развитие из
[архитектурной концепции](web_crawler_product_description.md) и [backlog](SCRUM.md),
а не заявленные возможности этой версии.

## Функциональные требования — 10

| № | Требование | Реализация и критерий приёмки |
|---|---|---|
| F1 | Регистрировать URL и заменять его метаданные. | `POST /urls`: `201`, одна запись на точную строку URL; повторный запрос заменяет поля. |
| F2 | Получать метаданные конкретного URL. | `GET /url-data?url=…`: сохранённая запись или `404`. |
| F3 | Просматривать URL постранично. | `GET /urls?limit=20&cursor=…`: массив `items`, не более `limit` элементов, `next_cursor` для продолжения. |
| F4 | Удалять URL из каталога. | `DELETE /url-data?url=…`: `204`; последующее чтение — `404`. Общий HTML других URL не удаляется. |
| F5 | Загружать HTML с привязкой к URL. | `POST /html`: сервер сохраняет содержимое, вычисляет SHA-256, записывает ссылку и время в метаданные; предварительная регистрация не нужна. |
| F6 | Читать сохранённый HTML по URL. | `GET /html?url=…`: исходная строка `html_content` в JSON; если страницы нет — `404`. |
| F7 | Объединять хранение одинакового содержимого. | Два URL с одинаковыми UTF-8 байтами HTML получают одинаковые SHA-256 и ссылку на один объект. |
| F8 | Находить URL по хешу содержимого. | `GET /urls?content_hash=…`: только записи с указанным SHA-256, с пагинацией. |
| F9 | Пакетно регистрировать URL. | `POST /urls/batch`: от 1 до 100 адресов; повторы внутри пакета исключаются, существующие записи сохраняются. |
| F10 | Получать статистику архива. | `GET /stats`: число URL, число записей с хешем и число различных хешей среди текущих метаданных. |

Проверки F1–F10: [tests/test_integration.py](tests/test_integration.py).

## Нефункциональные требования — 10

| № | Требование | Критерий и проверка |
|---|---|---|
| N1 | Сохранять данные между запусками. | После закрытия приложения и запуска с тем же файлом SQLite доступны прежние метаданные и HTML; `test_restart_persistence`. |
| N2 | Проверять входные данные до записи. | HTTP(S)-адрес до 2048 символов без логина, пароля и пробелов; хеш — 64 строчные hex-цифры; время ≥ 0; неизвестные поля запрещены. Нарушения — `400`; параметризованные тесты валидации. |
| N3 | Ограничивать объём запроса и ответа списка. | HTML ≤ 1 МиБ в UTF-8, тело HTTP-запроса ≤ 8 МиБ с учётом JSON-экранирования, пакет ≤ 100 URL, `limit` от 1 до 100. Превышение тела — `413`, остальных ограничений — `400`; тесты границ. |
| N4 | Быстро выдавать небольшую страницу локального каталога. | p95 < 200 мс для `GET /urls?limit=20` на 1000 записях, один клиент, 5 прогревочных и 50 измеряемых запросов через ASGI TestClient; `test_local_list_latency`. Это проверка API без сетевого транспорта, не SLA облачной системы. |
| N5 | Не блокировать цикл событий операциями хранилища. | SQLite вызывается через `asyncio.to_thread`, AWS — через aioboto3. 20 параллельных загрузок завершаются без потерь записей; `test_concurrent_writes`. |
| N6 | Возвращать предсказуемые ошибки. | Ошибки валидации — `400`, отсутствие данных — `404`, недоступность SQLite/AWS — `503`; JSON содержит `status_code` и `detail`, внутренние ошибки хранилища не раскрываются. `test_storage_failure_is_503`. |
| N7 | Выдавать HTML как данные без выполнения в интерфейсе API. | `GET /html` отвечает `application/json`, сохраняет исходную строку, включая теги; сервер не исполняет HTML и не обращается к переданным URL. `test_html_roundtrip_dedup_and_filter`. |
| N8 | Обеспечивать воспроизводимый локальный запуск. | Python 3.12 + `uv sync --frozen`; зависимости закреплены в `uv.lock`, SQLite создаётся автоматически, облачные ресурсы для локального режима не требуются. |
| N9 | Отделять конфигурацию от исходного кода. | Выбор хранилища, путь БД, регион и имена AWS-ресурсов задаются переменными окружения. Секреты не включаются в репозиторий; `.env` исключён из Git. `test_configuration`. |
| N10 | Поддерживать автоматические проверки качества. | Покрытие строк серверного кода ≥ 90%, pytest, Ruff, Black, isort и строгий mypy проходят. Команды ниже и workflow `.github/workflows/checks.yml`. |

## Запуск

Нужен [uv](https://docs.astral.sh/uv/getting-started/installation/).
Команды выполняются из корня репозитория:

```bash
git clone --branch codex/homework-part1 https://github.com/JumbikTank/nis_dz.git
cd nis_dz
uv sync --frozen
uv run --frozen uvicorn crawler.app:app --host 127.0.0.1 --port 8000
```

- API: <http://127.0.0.1:8000>
- Swagger UI: <http://127.0.0.1:8000/schema/swagger>
- OpenAPI JSON: <http://127.0.0.1:8000/schema/openapi.json>
- Проверка HTTP-сервера: <http://127.0.0.1:8000/health>

По умолчанию метаданные и HTML сохраняются в `data/crawler.sqlite3`.
`/health` проверяет только работу HTTP-приложения, а не доступность AWS.
Приложение рассчитано на локальную демонстрацию с общим каталогом, без аккаунтов
и разграничения доступа. Файл БД и его резервные копии в Git не добавляются.

Для своей конфигурации:

```bash
cp .env.example .env
# Изменить нужные значения в .env
uv run --frozen uvicorn crawler.app:app --env-file .env --host 127.0.0.1 --port 8000
```

## Пример работы

```bash
# Зарегистрировать URL
curl -i http://127.0.0.1:8000/urls \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://example.com"}'

# Сохранить страницу; метаданные URL обновятся автоматически
curl -i http://127.0.0.1:8000/html \
  -H 'Content-Type: application/json' \
  -d '{"url":"https://example.com","html_content":"<html><body>Hello</body></html>"}'

# Прочитать метаданные и HTML; --data-urlencode корректно передаёт URL с query-параметрами
curl -G http://127.0.0.1:8000/url-data --data-urlencode 'url=https://example.com'
curl -G http://127.0.0.1:8000/html --data-urlencode 'url=https://example.com'

# Пакетная регистрация
curl http://127.0.0.1:8000/urls/batch \
  -H 'Content-Type: application/json' \
  -d '{"urls":["https://example.org","https://example.net"]}'

# Каталог и статистика
curl 'http://127.0.0.1:8000/urls?limit=2'
curl http://127.0.0.1:8000/stats

# Удалить URL
curl -i -X DELETE 'http://127.0.0.1:8000/url-data?url=https%3A%2F%2Fexample.com'
```

Ответ `POST /html` содержит `url`, `s3_link`, `content_hash`, `last_crawled_time`.
Название `s3_link` сохранено для совместимости с исходным API: в AWS это
`s3://bucket/html/<hash>.html`, локально — `sqlite://html/<hash>`.
Это идентификатор хранения, а не HTTP-ссылка; читать страницу следует через `GET /html`.
Время — целое число секунд Unix UTC. При регистрации без явного времени сервер
подставляет текущее время; это не подтверждение фактического скачивания сайта.

`POST /urls` полностью заменяет метаданные: пропущенные `s3_link` и `content_hash`
становятся `null`. Для повторного добавления адресов с сохранением уже имеющихся
метаданных используйте пакетный метод. Повторная загрузка HTML заменяет текущую
связь URL с содержимым. Регистр URL, завершающий `/` и query-параметры не нормализуются.

Для следующей страницы передавайте `next_cursor` из предыдущего ответа через
`--data-urlencode`, сохраняя тот же фильтр. `next_cursor: null` означает конец.
SQLite сортирует URL лексикографически. В DynamoDB порядок определяется `Scan`:
отфильтрованная страница может быть пустой и при этом иметь следующий курсор.
Курсоры нельзя переносить между режимами хранения.

## Проверки

```bash
uv sync --frozen --extra dev
uv run --frozen pytest
uv run --frozen ruff check crawler tests
uv run --frozen black --check crawler tests
uv run --frozen isort --check-only crawler tests
uv run --frozen mypy crawler tests

# Отдельно вывести результат проверки задержки
uv run --frozen pytest tests/test_integration.py -k local_list_latency -s --no-cov
```

Тесты используют временные SQLite-файлы и не затрагивают рабочий каталог.
Unit-тесты AWS-адаптеров используют моки; интеграционные API-тесты работают
с настоящей SQLite. Проверки не требуют доступа к настоящему AWS.
Отчёт покрытия создаётся в `htmlcov/index.html`; порог 90% установлен в `pyproject.toml`.

## Дополнительный режим AWS

Установить `STORAGE_BACKEND=aws`. Потребуются уже созданные ресурсы:

- DynamoDB-таблица `DYNAMODB_TABLE` с partition key `url` типа String, без sort key;
- S3-бакет `S3_BUCKET` в регионе `AWS_DEFAULT_REGION`;
- credentials через стандартный механизм boto3: профиль, переменные окружения или IAM role;
- права DynamoDB `PutItem`, `GetItem`, `Scan`, `DeleteItem` и S3 `PutObject`, `GetObject`.

При необходимости `AWS_ENDPOINT_URL` задаёт endpoint совместимого локального эмулятора.
Сервер не создаёт облачные ресурсы сам. Секретные ключи в `.env.example` не записаны.
Для одного физического S3-объекта на хеш используйте бакет без versioning;
при включённом versioning повторная запись того же ключа создаёт версию.

Проверка на реальном AWS не входит в локальный прогон. AWS-список и статистика
используют `Scan` и предназначены для небольшого учебного каталога;
они не подтверждают производительность из старого архитектурного описания.

## Структура и ограничения

```text
crawler/
  app.py          # HTTP-маршруты, фабрика приложения, обработка ошибок
  models.py       # Контракты и валидация msgspec
  config.py       # Переменные окружения
  local.py        # Локальное хранение SQLite
  services.py     # DynamoDB и S3
tests/
  test_app.py         # Unit-тесты HTTP-маршрутов
  test_services.py    # Unit-тесты AWS-адаптеров
  test_integration.py # Полные сценарии API + SQLite
```

Сохранение HTML выполняется раньше обновления метаданных. При сбое второй операции
может остаться объект без ссылки; транзакция между AWS-сервисами не заявляется.
Удаление URL не удаляет общий объект HTML; сборка неиспользуемых объектов — дальнейшее
развитие. Статистика считает ссылки из метаданных, а не проверяет наличие объектов.
Пакетная регистрация проверяет все адреса до записи, но при сбое хранилища может
сохраниться часть пакета; повторный запрос допускается.

Основа реализации: [документация Litestar о запросах](https://docs.litestar.dev/2/usage/requests.html),
[обработка ошибок](https://docs.litestar.dev/2/usage/exceptions.html),
[sqlite3](https://docs.python.org/3/library/sqlite3.html).
